## Переносимо дані, а не лише назву каталогу

У розглянутому кейсі планувалося перенесення Docker на окреме сховище. Перевірка конфігурації показала, що `data-root` і `features` явно не задані. У виводі containerd були `root = "/var/lib/containerd"` і `state = "/run/containerd"`.

Це підстава перевірити обидва компоненти, а не оголосити один каталог усім сховищем. Самі шляхи containerd не доводять, що конкретна інсталяція вже використовує його image store. Режим сховища потрібно встановити окремо.

## Де закінчуються повноваження data-root

Для Docker Engine з containerd image store образи та snapshots можуть зберігатися окремо від Docker data directory. Налаштування `data-root` не змінює шлях сховища containerd. Для класичного storage driver картина інша — тому тут потрібні факти про інсталяцію, а не віра в універсальну схему.

Поточний Docker Root Dir можна перевірити без змін:

```bash
docker info --format '{{.DockerRootDir}}'
```

Цей результат підтверджує шлях Docker daemon. Він не є повною інвентаризацією всіх файлів containerd, bind mounts і зовнішніх сховищ. Мені теж хотілося закрити міграцію одним красивим рядком.

## Root і state — не пара валіз

`root` containerd призначений для довготривалих даних. `state` — runtime-стан; у розглянутій конфігурації він залишався під `/run`. Переносити все підряд на постійний диск лише заради симетрії назв не потрібно.

До копіювання треба визначити активний режим сховища, фактичні служби та mount нового носія. Узгоджене перенесення вимагає зупинки відповідних компонентів, тобто запланованого простою. У цій статті міграція не виконується.

## Що було планом, а не завершеним переїздом

У розглянутому кейсі запропонували зберегти права й числові UID/GID під час копіювання, перевірити конфігурацію та залишити старі дані для повернення. Після старту потрібно перевірити видимість образів, контейнерів, volumes і реальний стан застосунків.

Підтвердження завершеної міграції та післястартових перевірок у матеріалах кейсу немає. Назва цього розбору — саркастична теза про неповний план, а не твердження, що дані вже перенесли.

Ви перевіряйте результат. Я поки додам containerd у список учасників переїзду. Виявляється, його не можна замінити впевненим заголовком.
