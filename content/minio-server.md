## Що будуємо й навіщо

Успішний upload доводить запис об’єкта, а не відновлення; називати це backup без перевіреного restore — самообман, блядь.

### Дано

Є Debian-хост, окремо змонтований диск і застосунок або backup job, якому потрібний S3 API. MinIO приймає об’єкти: вміст файла, його ключ та metadata. Bucket — контейнер для об’єктів; ключ на кшталт `daily/report.tar` схожий на шлях, але не є звичайним каталогом Linux.

Це зручно для S3-сумісних клієнтів, артефактів і копій, які вже підготовлені backup-програмою. Це не SMB/NFS, не повна заміна сервісів AWS і не команда «зроби консистентний dump бази». Живу базу спочатку копіюють її штатним механізмом; завантаження відкритих database files саме по собі не робить їх придатними до відновлення.

### Що потрібно отримати

Один native MinIO-процес під systemd, дані на виділеному mount, S3 API за HTTPS і окремий backup-користувач. Root потрібний для адміністрування, а не для щоденного job. Console й API мають різні порти: 9001 та 9000 відповідно.

### Як перевіряємо

Перевірки йдуть від диска до сервісу, потім до API, ефективних прав і завантаженого назад файла. Це практичний посібник, а не опис зафіксованої аварії: наведені команди в цій інсталяції не виконувалися, поточний стан чужого сервера з них не випливає.

### Що вважаємо результатом

Сервіс запускається лише з потрібним mount, клієнт читає й пише в дозволений bucket, не має admin-доступу, а завантажений назад об’єкт збігається з оригіналом. Для реального бекапу далі потрібний тест відновлення самого застосунку.

## Спочатку стан самого MinIO

На момент підготовки матеріалу офіційний репозиторій MinIO Community позначений як archived і no longer maintained; репозиторій mc також архівний. README сервера описує source-only distribution, а старі готові binaries — як такі, що більше не оновлюються. Це важливіше за зручність старої команди wget.

Нижче — відтворюваний лабораторний рецепт Community, з зафіксованими ревізіями й власною збіркою. Для нового production спершу визнач підтримуваний продукт або дистрибутив, модель оновлень і вимоги до доступності. Поточний README посилається на AIStor, але його ліцензія й умови — окрема перевірка, а не мовчазна заміна Community у цьому рецепті.

## Як усе з’єднано

```text
S3-клієнт / backup job
        │ HTTPS :443
        ▼
reverse proxy на тому самому хості
        │ HTTP, тільки loopback
        ▼
MinIO API 127.0.0.1:9000 ──► /srv/minio/data

Адміністратор ── SSH tunnel ──► Console 127.0.0.1:9001
```

Приклад навмисно залишає backend на loopback. Якщо proxy живе в іншому контейнері чи на іншому хості, його 127.0.0.1 — інша машина або namespace: цей маршрут треба змінити явно й захистити. Прямі 9000/9001 в інтернет не відкриваємо.

Один вузол і один диск не дають HA. Дві папки на одному диску не додають незалежної копії. Versioning може допомогти від логічного перезапису, але не замінює іншу копію та політику захисту від видалення.
