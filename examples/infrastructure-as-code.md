### Було: заміну видно, але apply не має окремого запобіжника

Скорочений вигляд дій одного ресурсу в JSON plan, не конфігурація для застосування:

```json
{
  "change": {
    "actions": ["delete", "create"]
  }
}
```

Спочатку з’ясуй, який атрибут вимагає заміни. Якщо зміна випадкова — виправ її в HCL та створи новий plan. Якщо заміна потрібна — сплануй перенесення або відновлення даних.

### Запобіжник: заборонити випадкове знищення критичного ресурсу

Цей фрагмент додається всередину відповідного resource block, а не окремим файлом на верхньому рівні:

```hcl
lifecycle {
  prevent_destroy = true
}
```

prevent_destroy не усуває причину заміни: він змушує план із руйнівною операцією завершитися помилкою. Якщо прибрати весь ресурс із конфігурації, цей запобіжник більше не захищає його. Це додаткова межа процесу, а не заміна резервної копії.

### Перевірка після правки

```bash
terraform validate
terraform plan -out=review.tfplan
```

Захисти saved plan від стороннього доступу. Порівняй нові actions і причини зміни; не застосовуй старий plan після виправлення конфігурації. Повернення старого коду — лише нова пропозиція стану, а не автоматичне відновлення знищеного ресурсу.
