## Тепер корисне: розділи швидкість і помилки

Приклад для Linux із usbutils, util-linux та systemd. Нічого не від’єднує й не перевіряє диск записом.

### 1. Шлях пристрою

```bash
lsusb -t
lsblk -o NAME,TRAN,SIZE,FSTYPE,MOUNTPOINTS
```

`480M` описує режим USB-з’єднання, а не гарантовану швидкість файлового копіювання. Дерево контролерів допомагає зіставити порт і драйвер. `lsblk` дозволяє знайти поточний block device; імена на кшталт sda можуть змінитися після перепідключення.

### 2. Події навколо збою

```bash
export START_TIME='<START_TIME>'
export END_TIME='<END_TIME>'
journalctl -k --since "$START_TIME" --until "$END_TIME" \
  -o short-iso --no-pager
```

Потрібні події disconnect/reset, повторної реєстрації, I/O чи filesystem errors у тому самому інтервалі, що й симптом. Одна подія reset не визначає винуватця: варіанти включають кабель, живлення, bridge, диск і контролер.

### 3. Порівняльний тест

Якщо проблема відтворюється, змінюй лише одну умову: порт, кабель або живлення. Для від’єднання спочатку зупини записи й коректно демонтуй файлову систему — інакше додаси окрему проблему. Використовуй той самий workload і порівнюй журнал за однакові інтервали.

Відсутність помилок у короткому тесті не доводить довготривалу стабільність. `fsck` на змонтованій файловій системі та руйнівний write-test тут не потрібні.
